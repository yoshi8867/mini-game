## 1. 게임 개요

- **형식:** 20문제, 5지선다 OMR. 문제 '본문'은 없다. **정답 배열 자체가 퍼즐**이다.
- **명제:** 정답 배열에 대한 명제 24개. 학생 17~24명에게 **1인 1명제**를 무작위로 나눠 준다.
- **진행:** 학생들은 서로 정보를 주고받으며(거짓말·배신 허용) 정답을 추론하고, 각자 OMR을 제출한다.
- **난이도:** 정답을 다 맞히지 못해도 괜찮다고 사용자가 말했다.
- **학생 수 맞추기:** 학생이 24명보다 적으면 **☆(덜 중요) 명제**부터 뺀다. ☆ 7개를 모두 빼도 ★ 17개만으로 정답이 하나로 정해지도록 설계했다.
- **순서 해석:** 오름차순/내림차순은 **같은 값 불허(엄격)**로 정했고, 문제지 상단에 명시한다.

## 2. 설계 원칙 (사용자 지시, 반드시 지킬 것)

1. **숫자 묶음(세트)은 유지한다.** 사람이 인지하기 좋은 구조이기 때문이다.
   예: 1·2번, 1~5번, 3~5번, 5의 배수, 6~8번, 6~10번, 4의 배수, 홀수 번호, 16~20번, 6의 배수, 7·12·17, 3·6·9, 11~15번, 13~15번
2. **바꾸는 것은 술어다.**
   예: 같다 ↔ 내림차순 ↔ 오름차순 ↔ 모두 다르다 / 3이 없다 → 2가 없다
3. **결정적 명제는 판마다 반드시 바꾸고, 반복하지 않는다.**
   예: "홀수 번호 → 홀수 답", "(전체에) 4가 없다"
4. **범위가 너무 넓은 강한 명제는 범위를 좁힌다.**
   예: '전체에 4 없음' → '6~10번에 1 없음'
5. **홀수/짝수 번호(문제 절반)에 대한 힌트는 보수적으로 준다.** 보기를 1개만 지우는 형태가 적당하다.
   예: "홀수 문제의 답에는 3이 없다"
   주의: "짝수 문제는 답이 소수"는 보기를 2개 지워서 1판의 '홀수→홀수'와 강도가 같다.
6. **정보가 약해 거래가 안 되는 명제는 쓰지 않는다.**
   예: "1~20번 합은 67", "답이 1인 문제는 2개" → 대신 **"□번 답은 □"**를 쓴다.
7. **답을 직접 알려 주는 명제는 괜찮다.** 협력과 배신의 재료가 된다.
8. **"N번+M번 합은 □" 명제에는 짝을 둔다.** N 또는 M의 답을 직접 주는 명제가 짝이다. 짝끼리 합심하면 두 칸이 풀린다.
   - 허브(두 합 명제에 걸친 칸, 예: 15번)도 좋다.
   - 짝 명제는 되도록 ☆에서 뺀다.
9. **전체를 무작위로 다시 만들지 않는다.** 탐색 범위가 너무 크다. **몇 개 명제만 바꿔도 의미가 충분하다.**
10. **새 판 검증 조건 세 가지**
    - 24개 전부 참
    - 해가 유일
    - ☆ 7개를 빼도 해가 유일
    - (참고) 답 분포는 1~5가 각 3~5개 정도로 고르게

## 5. 검증 도구 — `OMR 명제 퀴즈\검증도구\`

실행 방법: `python <파일>`, 셸에서 `PYTHONIOENCODING=utf-8` 필요. 외부 패키지는 z3-solver만 쓴다(설치됨).

| 파일 | 내용 |
|---|---|
| `props.py` | **1판** 명제 P01~P24를 순수 Python 명제(True/False)로 정의. `python props.py 5 2 5 …(20개)` → 명제별 참/거짓 출력 |
| `props_original.py` | 사용자 원본 21개 명제(모순 있음) |
| `solve.py` | z3 인코딩, 해 탐색, 충돌(최소 제거 집합) 분석 |
| `round2.py` | **2판 생성기 겸 검증기 (자체 구현, z3 불필요)**. 주요 부품은 아래 참고 |
| `round2b.py` | **2판 최종본 재현.** `R.generate(2)` 정답·숫자를 쓰고, Q07·Q22·Q24를 직접 답으로 교체한 뒤 ☆ 7개를 고정하고 검증 |
| `star7.py`, `variants.py` | ☆ 7개가 가능한지, 직접 답 위치를 바꾼 조합 실험 |

`round2.py`의 주요 부품
- `PROPS`: (id, 템플릿, 범위, 판정 함수, 숫자 결정 함수) 목록
- `count_solutions()`: 전파와 탐색으로 해의 개수를 셈
- `propagate()`: 풀이 단계 로그를 남기는 전파
- `generate(seed)`: 구조 명제를 만족하고 분포가 고른 정답을 뽑아 숫자를 채움
- `render()`: 문제지 텍스트 출력

**새 판(3판)을 만드는 권장 절차**
1. `round2b.py`를 복사한다.
2. 위 원칙에 맞게 일부 명제의 술어나 숫자만 바꾼다.
3. 아래 세 가지를 반드시 확인한다.
   - `count_solutions(전체) == 1`
   - ☆ 제외 17개도 유일
   - `propagate` 로그로 풀이 흐름 점검
4. 바뀐 정답에 맞춰 숫자 명제를 다시 계산한다(숫자 결정 함수가 처리).
5. 문제지 txt 형식은 `(2판).txt`를 따른다: 상단은 문제, 구분선 아래는 출제자용(짝 / 빼는 순서 / 정답 / 풀이 / 바꾼 점).
